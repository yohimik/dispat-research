\section{Conformance}
\label{sec:conformance}

Each result below is testable, and most are tested. The table maps every
result to the specification section it formalises, the conformance cases
that exercise it, and the test that stands behind it. Cases are numbered as
the specification numbers them: a bare number is a vector of \SPEC{}
Appendix~B (B.7 for partial failure and catch-up, B.7a for optimisation
equivalence, B.9 for the channel axis, B.12 for shared-version groups),
``ec'' a row of the edge-case tables of \spec{15}, and ``\S27.10'',
``\S27.12'' and ``\S28.8'' the numbered vectors of those sections. Appendix~B
numbers two vectors 82c, so the table says which. A test name set alone is
in \code{services/dispat/internal/plan}; ``(int.)'' marks the black-box
integration suite \code{tests/integration}, whose plan states the claim each
test proves and, for the execution tests, the vector each one is written
against. The point of the mapping is that a result with no case and no test
is a claim resting on the proof alone, and the last two columns are where
that shows. The last block of the table runs the other way: protocol
requirements that have cases and tests but no numbered result in this
report.

Several rows deserve comment.

\Cref{thm:duality} has a test, and the test cannot fail. As
\cref{ob:duality} records, \code{Plan.StaleSources} returns the rows the
downward traversal recorded, and it still does: at \code{252216ba} it
returns \code{r.Sources} of the release, so
\code{TestStaleSourcesAgreesWithPropagation} compares a quantity with
itself. That is a reasonable engineering choice (an independent upward walk
would be a second implementation of the same rule, with its own bugs) but it
means the duality is asserted rather than checked here, and it is the reason
\cref{ob:duality} went unnoticed.
\code{TestSpec2RejectedBumpProducesNoStaleSourceRow} exercises the
observable eligibility result of edge case 135; the randomised cross-check
\spec{13.7b} recommends is the thing that would catch a disagreement, and it
needs a workspace with a prerelease train to do so.

\Cref{prop:screen} has no case and a test that checks the screen's shape
only. \code{TestPossiblyBehind} asserts that a provider's tag outside the
consumer's ancestry flags the consumer, that a never-released provider owes
nothing, that the ancestor relation clears the flag, and that no claim is
made without ancestry. Nothing checks the converse the proposition is about,
that a flagged consumer may owe nothing; the proposition rests on its proof.

\Cref{thm:g6} is the row whose test predates the normative fresh-window rule.
\code{TestPrereleaseTrainConvergesAfterRelease} opens with the words ``the
reported bug'': a package that entered a beta train and published
\code{1.0.0-beta.0} re-appeared in every subsequent plan as \code{beta.1},
\code{beta.2}, and so on. That is exactly \cref{ob:pre}, found in operation
rather than on paper, and fixed in the engine. CCME 2.0.0 then specified
$W_{\rm fresh}$ and the current text keeps it, so a second implementation
following the text discharges the prerelease work as the engine does.

\Cref{prop:bucket} had cases and no test when the engine traversed once per
unit. It no longer does: \code{propagate.go} serves every walk from a cache
keyed by source set, depth and edge kinds, holding each package's unbounded
walk and composing a unit's walk from its sources' walks when the unit names
at most eight of them, and walking outright otherwise. The vectors of
Appendix~B.7a are therefore no longer passed trivially.
\code{TestCachedWalkIsTheLiteralWalk} compares every route the cache can
take against the literal walk of \spec{9.2}, target for target and in order,
over 150 random workspaces that are dense on purpose, since diamonds and
sources that reach one another are where a composition goes wrong. The set
$X$ of \cref{prop:bucket} cannot arise, because the self-source exclusion is
applied per unit after composition, which
\code{TestSpec2SelfSourceCheckIsPerUnit} pins as edge case 138.

\Cref{prop:marker-pass} has no case: the cost workload at the end of
Appendix~B.7a is informative and states no threshold. Its test is the
definition itself: \code{TestAncestryIndexAgreesWithAWalk} checks the
bit-parallel marker pass against a walk per ancestry question over random
DAGs whose rank and topology are drawn independently, and
\code{TestUnionReadPlansExactlyAsPerBoundaryReads} runs the planner with the
union read hidden, one window per boundary, as it ran before the pass
existed, and requires the same plan.

The rows of \cref{prop:exec-placement} and of the last block rest on
the integration plan's claims. Each execution test names in its comment the
vector of \spec{28.8} it is written against, and the plan's Goal 57 states
the claim each proves; the section has thirty vectors, of which 20 and 26 do
not apply to the engine (\cref{ob:profile}). Vectors 28 and 29 of that
section, the create-only record after a lost lock and the documented
recovery of an abandoned one, are not named by any test, and the lock-loss
row does not claim them.

Three gaps are the ones the obligations name. Vectors 79 and 100a, the
optional dependency that does not block and the cycle that exists only
through \code{devDependencies}, have no test and fail against the engine
(\cref{ob:kinds}). The last two cases of vector 80d, the run the consumer
sits out and the refusal with \diag{E201}, have no test and the engine does
not implement them (\cref{ob:owed}). And the retry of a fleet record that
annotates the same commit has no test on the fleet path
(\cref{ob:records}).
