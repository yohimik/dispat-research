\title{Recovering Versioned Releases Across Build and Publish Boundaries}
\maketitle
\begin{abstract}
An npm engine, a Docker base image containing it, and an application image using that published base
and an npm SDK expose release failures: premature builds, forgotten packages
and changed retry versions.
We present a saga-inspired protocol that records per-package completion in Git and resumes
unfinished work with one release command.
Shared Windows/Linux CI/CD configuration spans languages, single-package
repositories, monorepos and linked repositories (polyrepos).
Commits control releases, holds, prereleases and tests; explicit scopes support
empty commits and a last-commit window targets retesting after repairs.
An agent skill guides diagnostics, plan review and automation.
Docker can supply language runtimes and deployment tools instead of host installations.
A Terraform integration reconstructs temporary state from cloud resources and
updates dependent deployments after infrastructure changes.
Deterministic, pure planning permits caches keyed by unchanged inputs;
specified extensions distribute tasks and releases.
Under explicit retry assumptions, the model gives eight guarantees, including stable versions
and idempotent recorded releases.
Exploratory outreach covers at least 211 repositories without estimating defect
prevalence. All 120 controlled fault episodes recover after repair; an analytical
alternative discarding intent after provider success loses work in 84.
Registry, CI, replay and scale experiments include google-cloud-node.
Native Windows equivalence and distributed execution remain unevaluated;
external effects require safe repetition or reconciliation.
Linux and LLVM results will be presented in the report.
\end{abstract}
