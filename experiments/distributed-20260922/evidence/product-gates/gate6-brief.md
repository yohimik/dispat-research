## Branch protocol (normative for this implementation; document it in code comments on the types)
- Branch name: `dispat-worker-<id>-<YYYYMMDD UTC>-<kind>-<32 lowercase hex from crypto/rand>`; `<id>` = the addressed node's name, `<kind>` in `probe|build|publish|prepare|snapshot|relay`. The name is an UNTRUSTED routing hint: a worker lists `refs/heads/dispat-worker-<id>-*` only, and never parses the date or kind for decisions. (A worker named `build` will also list `dispat-worker-build-a-…`; that is harmless: the signed manifest's `node` decides.)
- A branch is a first-parent chain of commits, each advanced by ONE compare-and-swap push by exactly one party: `assigned` A (orchestrator, create-only) → `claimed` C (worker) → [publish only, later gate: `ready` H (worker) → `go` G (orchestrator)] → `result` R (worker); `cancel` X (orchestrator, on tip A/C/H) → `ack` K (worker); then the orchestrator deletes the ref with a lease. Implement the state machine as an explicit type (states, legal transitions, who may write each) with a pure function deciding the next legal action from the observed chain, so it is unit-testable without git.
- Every commit's tree holds `dispat/<kind>.json` and `dispat/<kind>.sig`. The signature is lowercase hex HMAC-SHA256 over the EXACT blob bytes of the json (no canonicalization needed), verified with `hmac.Equal` on decoded bytes. The key is the value of the env var named by `execution.secretEnv`. Commit messages are inert (`dispat transport <kind>`), parents as the chain requires; the probe assignment has no source parent (root commit).
- Message schema (Go structs with json tags in `execution/protocol.go`, all fields documented): common header `{protocol int, kind, run, planDigest, task, attempt int, generation, node, branch, issuedAt RFC3339}`; assignment adds (for later gates; define now, leave unused fields empty): `repositories[] {name, path, snapshot}`, `package {name, repository, dir}`, `frame {login[], before[], commands[], after[]}`, `env[]` (computed DISPAT_* pairs), `staticEnv[]` (UNRESOLVED pairs), `shell[]`, `platforms[]`, `inputs[]`, `outputs[]`, `permits {publish bool, nativeRefs bool}`, `limits`; claim `{…header, assignment oid}`; result `{…header, assignment oid, status succeeded|failed|cancelled, failedPart, exit, platform{os,arch,dispat}, exports[], manifest[], outputTree, strayWrites}`; probe report = result with `report {protocol, dispat version, os, arch, capacity, gitVersion, limits}`. `const ProtocolVersion = 1`.
- Acceptance rules on the worker (ALL must hold, each failing rule has a stable reason enum logged at warn WITHOUT echoing contents): signature valid; `node` == this node's name (exact bytes); `branch` == the ref the commit was found on; `protocol` == ProtocolVersion; `issuedAt` within 24h either side of now (replay window; the branch date label is never parsed); `(run, task, attempt)` not in the persisted seen-set; chain shape legal (tip is A for a new claim). Size cap: the json blob is read with a byte cap (`transfer.maxManifestBytes`) BEFORE parsing.
- Reads: fetch the ref into the private namespace, then `ResolveFetchedCommit` to the exact OID; read blobs only by OID. Lost push response: re-read the remote tip; finding the intended OID there IS success (precedent: `carriesAttempt`, release/lock.go ~:253). A lease rejection is never retried blindly: re-read once and follow the state machine.

## `execution/mailbox.go`
`GitMailbox` (owns one endpoint + one local object store path + the gitx handle): `Assign(ctx, msg) (branch, oid)`, `Advance(ctx, branch, expectedOld, kind, json, extraTree…) oid`, `Observe(ctx, branches…) map[branch]Chain` (ONE `ls-remote` naming explicit refs or the node prefix, a `(ref, tip)` memo so unchanged refs cost nothing, fetch only new/moved refs in batches of 32), `Read(ctx, oid, kind) []byte`, `Close(ctx, leases…)` batched delete. ## `dispat worker` (`cli` + `app/worker.go` + `execution/worker.go`)
- CLI: new command word `worker` (cli/cli.go constants + usage + the services/dispat/README.md command table row if the cli tests require README/usage agreement: check `cli/*_test.go` for such a test; docs pages come in the docs gate). Flags: `--state-dir <dir>` (default: `os.UserCacheDir()/dispat/worker`), `--idle-timeout <seconds>` (0 = run until signalled; exit 0 after that long with no claimed work and no work in flight), plus the global flags that make sense (`--config`, `--root`, `--log-level`, `--log-format`). It must load the config WITHOUT requiring spaces/packages (see `validate(c, allowEmpty)` at config/config.go:962 and how `cmdInit`/`cmdScanner` bypass workspace composition in cli/dispatch.go `runConfigured`) and WITHOUT requiring the root to be a Git repository. Required settings, each an E225 refusal naming the key: `execution.name`, `execution.endpoint`, `execution.secretEnv` stated, and that variable set and non-empty. `execution.concurrency` (default 1) is the node's capacity. Either role may serve (`role: orchestrator` with name+endpoint serves tasks with worker authority and never reads its own `workers`). Refuse to start under worker authority (the gate-4 guard table gets the `worker` word).
- Loop (ONE goroutine owns polling, the memo, the seen-set and cancel signalling; claimed tasks run in their own goroutines under a `sync.WaitGroup`, bounded by capacity; a task is claimed only when a slot is free, so unclaimed work queues in the mailbox): tick = `Observe` node prefix → for each new tip: fetch, validate, decide via the state machine → for a valid `probe`: push C then R with the node report (probes do not consume a capacity slot; handled inline) → kinds this gate does not execute yet (`build`, `publish`, `prepare`) are not claimed at all: leave them untouched and log at debug (gate 7 implements execution). Back-off: 250 ms doubling to 5 s, reset on any progress; timers created with `time.NewTimer` and stopped on every exit path.
- State dir layout: `<state>/<name>/cache/<first 16 hex of sha256(endpoint)>.git` (bare, `git init --bare`, dispensable: if missing or corrupt it is recreated; fetches into it make later fetches incremental), `<state>/<name>/seen.json` (seen triples with timestamps, pruned past 24h, written atomically via temp file + rename), `<state>/<name>/tasks/` (per-attempt dirs; swept at start together with `git worktree prune` on the cache). A second worker started with the same state dir and name must refuse (lock file with PID; stale lock from a dead PID is taken over): otherwise two processes would race the seen-set.
- Shutdown: SIGINT/SIGTERM (use the same signal wiring the release command uses; find it in cli) or idle timeout → stop claiming, cancel in-flight task contexts, wait for the WaitGroup, exit 0 on idle/timeouts and on a clean signal stop (check how `release` maps interruption to exit codes in cli/README docs "Interruption" and mirror for a serving command; document the choice).
- Logging per the plan's logging map: info `worker started` (name, redacted endpoint, concurrency, stateDir), `task claimed`, `task finished`, `worker stopped` (reason idle|signal); warn `assignment rejected` (reason enum, branch, never contents); debug `assignment inspected`; trace each tick and memo hit. Fields `node`, `branch`, `run`, `task`, `attempt`, `commit`.
