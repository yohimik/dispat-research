## 2. Prepared input snapshot per dispatch (`execution/coordinator.go`, using gitx Plumbing)
- The guard is a `sync.RWMutex` owned by the Coordinator: `Guard` takes the READ side for the duration of a version/syncLock frame (many writers may overlap each other exactly as today; syncLock keeps its own budget) plus one slot of the local node semaphore sized by the entry `execution.concurrency`; `Build` takes the WRITE side only while it snapshots (so no manifest or lockfile write is torn), then releases it before dispatching.
- Snapshot of one repository = a commit whose parent is the PLANNED head of that repository (`Plan.RepositoryHeads`, or HEAD of the root for single history: use the value the digest input used) and whose tree is that head's tree plus the working tree's current tracked modifications and untracked-unignored files: copy the repository's real index file to a temp path (`git rev-parse --git-path index`; preserves stat data so unchanged files are not rehashed), `GIT_INDEX_FILE=<copy> git add -A`, `git write-tree`, `git commit-tree -p <planned head>` with the fixed transport identity and the inert message. One snapshot per repository in the package's input closure (`Plan.RepositoryInputOrder`/`RepositoryInputs` bitsets; single history = the root only). Cache by (repository, tree OID): when the tree did not change since the last dispatch reuse the commit (saves pushes). Temp index removed on every path.
- The assignment's branch is created with A whose single parent is the OWNER repository's snapshot (so one push carries the source; later pushes are incremental because every snapshot descends from the planned head). Snapshots of OTHER repositories in the closure are pushed as their own immutable `…-snapshot-…` branches to the same endpoint (create-only, never advanced) and named in `repositories[]` as `{name, path (workspace-relative checkout path, "." for the root), snapshot oid, branch}`. In multi-repository modes each repository has its own object store: build each snapshot in ITS repository and push from there.
- Never touch the real index, HEAD, branches or the working tree of any repository. Add a unit test that the real index bytes and `git status --porcelain` are unchanged by a snapshot, and one that a concurrent writer holding the read guard is never observed half-written (write a large file in chunks under the read side while another goroutine snapshots; the snapshot either has the old or the complete new content).

## 3. Placement and capacity (`execution/pool.go`)
- `Pool` built from the preflight reports: per node a counting semaphore of `min(report.capacity, …)` slots, health flag, platform. `Acquire(ctx, platforms) (*Lease, error)` picks a healthy compatible node with a free slot (deterministic preference: fewest in-flight, then name order), blocking with context. Preflight already refused a platform no configured node satisfies, so during a run the only way to have no node is that every compatible node became unhealthy: then `Acquire` fails the waiting task at once (bounded wait, never a hang) with E227, the message naming the platform and the unhealthy nodes. A task that timed out on a node fails with the same code.
- A slot is returned ONLY on a terminal result (R) or an acknowledged cancel (K; gate 12 adds cancel). In this gate a task that exceeds `timeouts.task` marks the node unhealthy and the slot LEAKED (never returned), the task fails; gate 12 refines. Stage budgets are not multiplied: the build task already holds its `graph.Drain` build slot while it waits for a node (nothing to do, but assert it in an integration test).
- The worker enforces its own capacity across runs by claiming only when a local slot is free (gate 6 loop); unclaimed assignments wait in the mailbox.

## 5. Coordinator.Build
snapshot → `Pool.Acquire` → `Assign` build assignment (header: run, planDigest, task `<package>:build`, attempt 1, generation, node, branch) → info `task assigned` → poll `Observe` on that branch until R (or `timeouts.task`) with the mailbox back-off (one `ls-remote` per endpoint per tick covering ALL in-flight branches of this coordinator: a single observer goroutine owned by the Coordinator fans results out to waiting Build calls over channels; no per-task polling loops) → validate R (signature, header echo equals assignment incl. generation and assignment OID, chain A→C→R first-parent with A the exact OID created) → stale/duplicate/forged results are ignored with a warn (E226 category) and waiting continues until timeout → success: info `task finished`, return exports; failure: error carrying the failing part. `strayWrites > 0` → warn W244. Context cancellation (run interrupted) → stop waiting, mark the attempt abandoned; `Close` deletes its ref (gate 12 adds X/K). All refs this run created (tasks + snapshots) are deleted in `Close` by batched lease deletes per endpoint; a delete failure is W244 and never changes package outcomes.
