# Gate 8: output manifests (capture, validate, install): library + unit tables

`services/dispat/internal/execution/manifest.go` and `worktree.go` (extend if gate 7 created it).

## Capture (on the node that ran the build, after a successful frame)
- Inputs: the package's checkout dir, its repository worktree, declared roots (`buildOutputs`, literal, slash paths relative to the package dir), limits (`maxFiles`, `maxBytes`).
- An absent declared root FAILS the task (E227 `io-integrity`): a build that did not produce what its configuration promises cannot satisfy a consumer.
- Tree construction: empty temp index (`GIT_INDEX_FILE`), `git --literal-pathspecs add -f -- <roots>` inside the package's repository worktree (`-f` because outputs are usually ignored; literal pathspecs so a name with glob characters is a name), `git write-tree`, then take the subtree under the package dir so manifest paths are package-relative. Use gate 5's Plumbing; if a needed primitive is missing add it there with a unit test.
- Walk `ls-tree -r -l -z` as a STREAM: refuse (before any commit is made) mode 160000 gitlinks, anything that is not a blob (100644/100755) or a symlink (120000), two paths equal after case folding, more than `maxFiles` entries, a running size sum above `maxBytes`. 
- Digests: sha256 of each blob's content, read through ONE `git cat-file --batch` process, each object streamed with `io.CopyN` into the hasher (never a whole file in memory; symlinks: digest of the link target string, and `target` recorded).
- Manifest entry `{path, type file|symlink, mode "0644"|"0755", size, sha256, target}`; entries sorted by path. The manifest binds: run, planDigest, task, attempt, generation, node, package name and planned version, the snapshot OIDs the build consumed (repository-qualified), platform `{os, arch}`, declared roots, and `inputs[]` = for every provider output set installed for this build `{package, outputTree, manifestDigest}`; plus `outputTree` (the tree OID) and `manifestDigest` = sha256 over the manifest's canonical JSON with that field empty. R's tree adds `outputs/` = that tree.

## Validate (ONE function used by the consuming worker AND by the orchestrator at admission)
Given a manifest, the tree it names, the consumer's expectations: every manifest path is slash-separated, relative, no `..`, no empty/`.` component, no `.git` component, no backslash, no colon, no NUL, lies under one of the declared roots; symlink `target` is relative, never absolute, and, resolved lexically from the link's own directory, stays inside the link's declared root; modes only 0644/0755 (+ symlink); manifest and `ls-tree` of `outputTree` agree exactly in count, path, type, mode and size (a manifest naming a file the tree lacks, or the reverse, fails); totals within limits; `platform` is acceptable to the consumer (`buildPlatforms` of the CONSUMER package, empty = any); the header identities equal what the caller expects (run, planDigest, generation, task, attempt); `manifestDigest` recomputes. Each rule has its own stable reason (enum) for logs and tests. Any failure = E227 and the prerequisite is unready: the consumer's commands never start.

## Install (materialize a verified output set into a checkout)
- Stage under `<taskDir>/.dispat-staging/<provider package>/`: create directories, stream every blob from `cat-file --batch` to its file with the manifest mode, hashing while writing and comparing to the manifest digest (a mismatch aborts and removes the staging dir); create symlinks last. Before writing each path check with `Lstat` that no parent component inside staging is a symlink (no following links while writing). No platform-specific open flags (TinyGo and Windows builds must compile).
- Then for each declared root: if the destination exists, rename it aside (`<root>.dispat-old-<random>`), `os.Rename` the staged root into place, remove the aside copy; on failure restore the aside copy. All roots of ALL inputs are installed before any command of the consuming task starts: that ordering is the atomicity at the task-input boundary.
- A worker sweeps stale `.dispat-staging` and `*.dispat-old-*` leftovers of its task dirs at start (extend gate 6's sweep).

# Gate 9: transfer end to end

## Worker side
- After a successful build frame: capture → R carries `manifest`, `outputTree`, and `outputs/` in its tree (one CAS push; the pack contains the blobs). A capture failure turns the result into `failed` with `failedPart: "outputs"` and the reason enum.
- Before a build frame: for every entry of the assignment's `inputs[]` of kind `outputs` (`{package, endpoint-local branch, commit (the provider's R oid), manifestDigest, path (the provider package's workspace-relative dir)}`): fetch that branch into the bare cache, `ResolveFetchedCommit` to the exact R oid (never the moving tip), read `dispat/result.json` at that oid with the size cap, verify signature, run the shared validator with `manifestDigest` from the ASSIGNMENT as the expected digest (the orchestrator admitted exactly that manifest), then install into the provider package's dir inside this task's checkout. Any failure → R `failed`, `failedPart: "inputs"`, reason enum; no command ran. Missing bytes (a branch or oid that cannot be fetched, a tree missing a manifest file) is the same failure: a digest, filename or branch reference without retrievable bytes fails (vector 25).

## Orchestrator side (`Coordinator`)
- Admission of a build R: signature + header echo (gate 7) + the shared validator against `outputTree` (fetch R into the entry repository's object store: objects only, private ref namespace, deleted on Close) with the PRODUCER's declared roots from the plan → info `outputs admitted` (package, files, bytes) and the admitted `(R oid, branch, endpoint, manifestDigest)` recorded per package in the Coordinator (single owner, guarded). Rejection → the package fails at `build` with E227, consumers are blocked by the ordinary rules (W194), nothing is substituted: no registry fallback, no silent rebuild.
- `Build(consumer)` computes inputs = admitted outputs of every package in the consumer's TRANSITIVE provider closure that declares `buildOutputs` and is releasing in this run (non-releasing providers arrive in gate 10), over ALL dependency kinds present in the graph (`p.Providers`; check whether dev/peer/optional edges are in `Plan.Providers` or a separate structure and include them: a build-only edge outside propagation kinds still supplies bytes, vector 22; if reaching those edges needs plan changes, stop and report instead of changing the planner).
- Keep-alive: a provider's branch is NOT deleted while any consumer that needs it is non-terminal (reference counts in the Coordinator; `Close` deletes everything at the end anyway).
- Relay: when the consumer's node has a DIFFERENT endpoint than the producer's, push the producer's R oid to the consumer's endpoint as an immutable create-only branch `dispat-worker-<consumer id>-<date>-relay-<random>` first (objects are already in the entry repository's store after admission) and name that branch in `inputs[]`. Same endpoint → name the producer's branch directly.
- Orchestrator-side install: after admitting a RELEASING package's outputs, install them into the orchestrator's own checkout of that package (same install routine, staging under a run-scoped temp dir inside the repository's git dir or os temp, never inside tracked paths), so local stages that follow (publish in this gate's branch state, recorders that upload files named by `DISPAT_EXPORT_GITHUB`, `postPublish`) see the bytes. This happens inside `Build` before it returns.
- Logging per the plan's map: debug `result fetched`, `outputs verified` (files, bytes, took), `relay pushed`; info `outputs admitted`; warn for rejected outputs carries the reason enum and identities, never manifest bodies.
