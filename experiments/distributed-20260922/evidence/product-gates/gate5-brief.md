## 2. Compare-and-swap transport plumbing: `services/dispat/internal/gitx/transport.go` (new) + tests against temporary bare repositories
All remote arguments are preceded by `--` where git allows, every logged URL goes through `RedactURL`, every invocation goes through the package's existing runner so trace logging and redaction keep working. Operations (methods on `LocalGitx` behind a NEW small interface `Transportx` declared where it is consumed later, or, if gitx keeps its interfaces in-package, mirror how `LockGitx`/`UnionHistoryx` optional capabilities are declared):
- `PushCreate(ctx, remote, oid, branch)`: atomic create-only: `git push --force-with-lease=refs/heads/<branch>: <remote> <oid>:refs/heads/<branch>` (empty expected value = the ref must not exist). Do NOT use `PushBranchAt` (gitx.go ~:1975): it is ls-remote-then-push, a check-then-act race. Distinguish "lease rejected" (someone else holds the name or the ref moved: a typed sentinel error `ErrLeaseRejected`) from transport failures, WITHOUT parsing human git wording: use `git push --porcelain` and its machine-readable status flags (`!` rejected / `*` new / ` ` fast-forward), which is what existing lease code in this package should already do: read `DeleteRemoteTagLease` (~:1556) and `PushObjectToTag` (~:1533) and mirror their result parsing.
- `PushAdvance(ctx, remote, oid, branch, expectedOld)`: same with `--force-with-lease=refs/heads/<branch>:<expectedOld>`.
- `DeleteRemoteBranchesLease(ctx, remote, []BranchLease{Branch, ExpectedOld})`: ONE push deleting many refs with a lease each (`--force-with-lease=<ref>:<old>` per ref, `:refs/heads/<b>` refspecs), reporting per-ref outcomes from porcelain output.
- `ListRemoteHeads(ctx, remote, pattern)`: `git ls-remote --heads -- <remote> <pattern>` → `[]RemoteHead{Name, OID}` sorted by name; bounded output (refuse more than a documented cap, e.g. 10000 refs, with a typed error) so a hostile mailbox cannot exhaust memory.
- `FetchRefs(ctx, remote, []string refs)`: one `git fetch --no-tags --no-write-fetch-head -- <remote> +refs/heads/<b>:refs/dispat-transport/<b>` batch (cap 32 per call; the caller batches), into a private ref namespace that never collides with branches or tags, plus `DeleteLocalTransportRefs`.
- `ResolveFetchedCommit(ctx, localRef, wantOID, maxDepth)`: proves `wantOID^{commit}` exists (`cat-file -e`) and is the tip of `localRef` or on its FIRST-PARENT chain within `maxDepth`, returning nothing but an error: callers then read only from `wantOID`. Never uses FETCH_HEAD.
- `RemoteTagObject(ctx, remote, tag)`: the OID the remote advertises for `refs/tags/<tag>` (the tag OBJECT id, not the peeled commit; see how release/lock.go reads the lock), `""` when absent.
- A sticky-error plumbing session type (one struct, e.g. `Plumbing`, created per operation; after the first failed step every later step is a no-op and `Err()` returns the first error, so a multi-step tree construction has ONE error arm per step for tests) with: `HashObject(r io.Reader) oid` (streams stdin into `git hash-object -w --stdin`, never buffers the whole blob), `MakeTree(entries)` (`git mktree -z`), `CommitTree(tree, parents, message, identity)` (sets GIT_AUTHOR_NAME/EMAIL and GIT_COMMITTER_NAME/EMAIL + dates in the child env explicitly: a worker's bare cache clone has no user.name; identity is a fixed dispat transport identity constant; message is inert text like `dispat transport <kind>` that can never parse as a bump-producing CCME unit), `WriteTreeFromPaths(dir, indexFile, paths, force)` (temp `GIT_INDEX_FILE`, `git --literal-pathspecs add [-f] -- <paths>`, `git write-tree`), `ReadBlob(oid, w io.Writer, maxBytes)` (size checked with `cat-file -s` BEFORE streaming; refuses larger than max with a typed error), `ListTree(tree, fn)` (streams `ls-tree -r -l -z`, NUL-scanned, calls fn per entry, never builds the whole listing in memory), `WorktreeAdd(dir, oid)` / `WorktreeRemove(dir)` / `WorktreePrune()`.
- Unit tests in `gitx/transport_test.go` with real temp bare repos (this package already builds small real repositories in tests): create-only succeeds once and the second create gets `ErrLeaseRejected`; advance with right/wrong expected; batched delete with one stale lease reports that one and deletes the others; list cap; fetch + resolve (tip, first-parent ancestor, non-ancestor refused, second-parent-only ancestor refused, missing object refused); blob size cap; tree listing streaming with names containing spaces/unicode/newlines; commit identity present with `HOME` pointed at an empty dir and no global config (`GIT_CONFIG_GLOBAL=/dev/null`); sticky error stops later steps; every logged URL is redacted (the package has redaction tests to mirror: gitx/redaction_test.go).
