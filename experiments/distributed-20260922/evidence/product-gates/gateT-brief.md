## The defect
`dispat release` takes the remote release lock before planning (services/dispat/internal/app/release.go: `acquireReleaseLocks` → `planUnderLock`), but the plan reads release tags from the LOCAL clone and nothing under the lock compares them with the remote. `checkNotBehind` / `gitx.BehindRemote` (services/dispat/internal/gitx/gitx.go ~:1784) checks only the branch tip, and a release that writes nothing to commit pushes tags on the planned head without moving the branch.
Reproduction 1: bare remote; clone `a` with one package `packages/core/package.json` and a config with `changelog.enabled: false`, `commit: {enabled: true, push: true}`, a build and a publish script that appends `$DISPAT_PACKAGE@$DISPAT_NEW_VERSION` to a registry log, one space over `packages`; commit `feat(core): first`, push main; clone `b` NOW (it has no tags). `dispat release` in `a` publishes core@0.1.0 and pushes the tag with no release commit. `dispat release` in `b` takes the lock, plans 0.0.0 → 0.1.0 AGAIN, runs publish again, logs "tag already existed on the remote and was overwritten", exits 0.
Reproduction 2: add a commit in `a`, push, `git clone --no-tags` as `c`, release there: core@0.1.0 is published a third time from the new commit and the remote tag core@0.1.0 is MOVED to it, violating SPEC §19.1 (tags MUST NOT be moved once pushed). The doc comment on `CommitConfig.Force` (pkg/models/models.go ~:672-680) claims a release tag sitting at a different commit is left alone; that is not what happens on the remote.
First reproduce both with the current binary in a scratch directory (build it fresh) and keep the scripts' essence for the integration tests.

## The fix
1. Comparison under the locks, before the plan is computed. In `planUnderLock` (after the locks are held, next to `VerifyRemote`/`checkNotBehind`, and before `selectedPlan`/`plan.Compute`), for the single repository and for EVERY participating repository of a composed workspace (control repository, imported sources, linked peers: look at how `workspaceRecorder` iterates participating repositories and at `captureSnapshot`, services/dispat/internal/app/polyrepo_snapshot.go ~:48-109, which already builds a per-repository matcher of release-tag namespaces through `tagNamespaces`): read the remote's tags ONCE per repository (`git ls-remote --tags`; see `gitx.RemoteTags` and the peeled reads in services/dispat/internal/gitx/polyrepo_write.go ~:50; you need the PEELED commit of annotated tags: `ref^{}` lines), keep only RELEASE tags of that repository's packages (parse with the packages' tag formats; ALIAS tags and the lock tag `dispat-release-lock` and its attempt tags are excluded: alias tags legitimately move), and for each remote release tag:
   - its commit is not present in the local object store → it cannot be reachable from the planned head: ignore it (SPEC: "a commit the checkout does not hold cannot be reachable from its head");
   - its commit is reachable from the planned head and the local repository has no such tag → `E196` (incomplete history), naming the repository, the tag and the remedy "fetch the remote's tags (`git fetch --tags`) and run again";
   - the local tag of the same name peels to a different commit → `E191`, naming both commits; nothing is repaired or moved;
   - identical → fine.
   Never refresh silently: the engine does not fetch; it refuses. The refusal happens before any hook, build or publish, releases the locks through the existing deferred cleanup, and exits non-zero. One `ls-remote` per repository, O(T); one ancestry question per tag the input lacks (none in the ordinary case): use the existing ancestry helpers (`IsAncestor`/commit graph in gitx) rather than a fork per tag when many are missing (batch with `git merge-base --is-ancestor` only if nothing better exists; say what you chose).
   Scope rules: read-only commands (`status`, `preview`) take no lock and make no comparison. A run that pushes nothing has nothing to compare: skip when the repository's effective commit policy does not push (`commit.enabled && commit.push` false; in a composed workspace per repository, using the same effective policy the recorder uses). Respect `commit.verify: false` exactly the way the existing up-front `ls-remote` checks do (find `IsVerifyEnabled` call sites): when verification is off, skip the comparison and say so at debug level. The lock bypass does not skip the comparison (the comparison is about records, not about exclusion), but without a remote configured there is nothing to read: follow what `VerifyRemote` does in that case.
   Codes: `E191` and `E196` already exist in the planner's registry (services/dispat/internal/plan/plan.go, const block ~:55-515): reuse the constants, do not invent codes. Return errors through the mechanism that makes `logError` print the code (`config.WithDiagnostic` or the execution `Diagnostic` type; pick the one the release path already uses for E330-class refusals).
2. Release tags are created, never replaced, on the remote. Find where release tags are pushed (`dispat commit --tag --push` path and the release finalize path: services/dispat/internal/app/finalize.go `mergeAndPush`/`refuseRepublishing` ~:274-441, services/dispat/internal/gitx push helpers, and the fleet recorder's tag pushes in app/polyrepo_record.go) and where "tag already existed on the remote and was overwritten" is logged. Make the push of a RELEASE tag create-only: if the remote already holds that tag name peeling to the SAME commit, that is success (the retry of an uncertain write, SPEC §19.4: keep the existing W223-style "already recorded" reporting); if it peels to a DIFFERENT commit, the tag is left alone, the package keeps its `published` status, and a critical diagnostic is recorded with the existing code for a tag at another commit (`E221` `CodeTagAtOtherCommit`), exactly as the local-tag case already does. Only ALIAS tags with `moving: true` are pushed with force. `commit.force` (default true) keeps meaning "do not fail because an identical ref exists" and never means "move a release tag": correct the doc comment on `CommitConfig.Force` in pkg/models/models.go so it is true, and check packages/docs/docs/configuration for the same sentence.
   Use a lease/atomic form so the check and the write are one remote operation (for example `git push --force-with-lease=refs/tags/<t>:` create-only, and read the remote's answer from `--porcelain` flags through `runStream`, the way services/dispat/internal/gitx/transport.go `pushLeased` does; note `run`/`runEnv` return an empty string beside an error by contract: do not change that).
