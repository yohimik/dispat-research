- Overheads with warm caches: preflight probe about 4 s; source push 0.03-0.05 s once the harness shrank to the image-only export (512 KB); kernel worktree checkout 7-8 s PER CELL; assignment to claim 1-4 s; result to coordinator 1-5 s; scheduler queue gaps 0 s.
- Two placement facts that decided round 1: a heterogeneous pool makes the release wait for the slower worker (dispat places a ready package on any free node; it has no notion of node speed), and batching cases inside one package keeps the build-directory reuse the reference enjoys while splitting exposes them to more workers at the price of one checkout and dispatch per cell.

## dispat facts you may use (do not look for more in the dispat sources; ask if a fact is missing)
- Config keys per package (ladder keys, nearest statement wins): `runOnly: both | worker | orchestrator` (or a `[build, publish]` pair): `orchestrator` runs the stage on the machine that runs `dispat release`, `worker` only on a `dispat worker` node, `both` places on a free worker first and on the orchestrator's own slot last. `buildPlatforms: [linux/amd64]` filters nodes by os/arch only. `execution.concurrency` is the orchestrator's own build capacity when it takes part; `execution.workers: [{name, endpoint}]`; `execution.timeouts.{preflight,task,cancel}`; `execution.transfer.{maxFiles,maxBytes,maxManifestBytes,timeout}`; `buildOutputs` (not needed here: the cells export counts, they carry no files).
- This gives you exactly TWO placement classes: packages pinned to the orchestrator machine and packages pinned to workers. There is no per-worker pinning and no speed-aware placement (that is a dispat follow-up; note in the report what such a hint would have bought you, with numbers).
- Worker command: `dispat worker --root <dir with dispat.json> --state-dir <dir> --idle-timeout 0 --log-level debug` (see `dispat/gce/worker.sh`). The orchestrator: `dispat release --config <file> --log-format json --log-level debug`. Timed messages in the JSON logs: `release plan ready`, `worker ready`, `task assigned`, `task claimed`, `task finished`, `outputs admitted`; the summary at the end lists placement per task.
- The mailbox is a bare Git repository the workers reach over ssh (`dispat/gce/orchestrator.sh` creates it and authorises the key). Snapshot branches are pushed once per changed working state; results come back as branches. The worker's poll back-off is 250 ms to 5 s (not configurable), which is where the 1-5 s claim and result latencies come from.
