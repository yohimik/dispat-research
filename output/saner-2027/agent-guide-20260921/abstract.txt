Distributed releases must transfer dependency outputs and preserve unfinished work after provider success. Our protocol combines deterministic planning, stage-aware scheduling, and consumer-owned release obligations. Release planning is a pure function of fixed history, records, graph, and configuration. An accompanying agent guide lets coding agents inspect plans and invoke CI releases through this deterministic engine. A proposed execution profile adds workers to single repositories, monorepos, and polyrepos. Nodes share one configuration schema and default to orchestrator capability; explicit workers cannot initiate releases. The CI-entry node locks all participating repositories and assigns planned tasks to linked workers within concurrency limits. Temporary Git branches synchronize changes; verified output transfer lets remote JavaScript consumers reuse provider builds without rebuilding their prerequisite closures. Publication retains dependency gates and source-owned records. The single-history model gives eight conditional mathematical recovery guarantees. All 120 controlled fault episodes recover after repair; an analytical source-discharge alternative loses unfinished work in 84 (70%). This compares admission rules, not competing tools or production failure rates. Distributed execution remains unimplemented and unmeasured; full implementation refinement and external exactly-once effects remain outside the claims.
